## Problem Statement

collegedata.fyi already joins school-authored Common Data Set reports with
College Scorecard and NCES/IPEDS. CDS has no repayment field. The school page
federal-outcomes band shows earnings, graduation, net price, and median debt —
not whether borrowers are paying. Scorecard already stores `repayment_rate_3yr`
and `default_rate_3yr` (official cohort default rate, CDR) and never displays
them. ED says those series are pandemic-broken and now publishes a different
public institution-level **nonpayment rate** (Direct Loan borrowers who entered
repayment January 2020–May 2025 and were 90+ days delinquent at a dated pull).
We do not host that file. We also do not store OPEID, the key it uses.

This is not a CDS competitor. It is a Title IV outcomes companion. It is not a
fourth named homepage source.

## Status Quo

A counselor or reporter opens `/schools/{slug}` and sees Scorecard debt and
10-year earnings. They cannot see current delinquency. API consumers can
request `repayment_rate_3yr` / `default_rate_3yr` from `scorecard_summary`;
those fields are unused in `OutcomesBand`. Directory and Scorecard loaders are
UNITID-only. `load_directory.py` does not persist OPEID even though the annual
Scorecard CSV includes it. `MAIN` is already mapped to `main_campus`. There is
no `tools/fsa/`, no vintage store, no probe. Endowment reconciliation already
has `normalize_opeid6` in `tools/ipeds/reconcile_endowment_scorecard.py`.

Three school-page call sites already exist: CDS landing `OutcomesSection`,
directory-only landing, and year pages via `OutcomesBand`. Outcomes currently
render only when Scorecard is present. Year pages skip `OutcomesBand` when
`doc.sub_institutional`.

## Target User & Narrowest Wedge

Primary users (from the pasted plan, not a named person): college counselors
comparing aid/outcomes on a school page; local reporters checking one campus.
Researchers get the same number via PostgREST.

Narrowest public wedge: one school-page KPI, source-labeled ED/FSA, with
as-of date and "not the official cohort default rate." Probe and a ≥25% recipe
are later slices. A ≥40% ranking page is out.

## Constraints

- Voice (`web/VOICE.md`): homepage/About name CDS, IPEDS, and College
  Scorecard. FSA is cited on the number, not added to the promise.
- Never label nonpayment as CDR. Do not narrate "predatory."
- Identity: public slug is `schools.yaml` `id`; universal join is IPEDS
  UNITID. FSA is OPEID. Fail closed on ambiguous branch maps. Do not inherit a
  parent OPEID onto sub-institutional CDS rows.
- Migrations apply from `main` only.
- Scratch downloads go to `scratch/fsa/`, not `tools/`.
- Existing deploy path (Vercel + PostgREST) covers distribution.
- 90/10 Title IV revenue share is a different file we do not host. Out of
  scope.

## Premises

1. Companion to Scorecard, not a fourth named homepage source.
2. The hole is definition (90-day delinquency, 2020–2025 repayment entry,
   dated pull), not missing Scorecard columns.
3. Join quality is the spike: OPEID 6 vs 8 digit and chain campuses (UEI,
   Miller-Motte) before any UI.
4. First public surface is the school-page strip. No ≥40% list. ED's cut is
   25% if a list ships later.
5. No NSLDS DELQ01. No 90/10 pairing in this design.

## Approaches Considered

### Approach A: Show unused Scorecard repayment/CDR; FSA stays a scratch notebook

Ruled out: publishes the series ED says not to trust as the product answer.

### Approach B: Latest-row table after the join spike (no vintages, no probe, no recipe)

Ruled out by choice. The delta that matters vs B is **append-only vintages**,

Two tables + one serving view. OPEID on the directory. School-page KPI.

## Recommended Approach

One public workbook, not a clone of IPEDS. Two tables, one serving view,
Scorecard-style column-drift abort, IPEDS-style dry-run/`--apply`. Do not
clone `ipeds_tables`, raw rows, value labels, or the 10-month probe window.

**Why this and not B:** three public vintages already exist (Jul 2025, Feb
2026, May 2026). Latest-only upsert would overwrite the post-pause series.
Probe and recipe are not why C wins.

### Identity and join

Add `opeid` (8-digit text, zero-padded) and generated/stored `opeid6` as
`left(opeid, 6)` to `institution_directory` from Scorecard CSV `OPEID` in
`load_directory.py`. Do **not** call `normalize_opeid6` on the 8-digit
column (it pads the whole integer to 6 and would turn `00100201` into
`100201`). If Scorecard also ships `OPEID6`, assert it equals `opeid6`.
Extract `normalize_opeid8` if the pad logic needs a shared helper.
`opeid` becomes a public directory field (existing RLS is `USING (true)`).
Document it on `/api`. Do not re-read Scorecard `MAIN` at FSA join time;
use `main_campus`.

Join is computed in the serving view from current directory rows, not frozen
on facts (so a directory OPEID backfill rematches without a fact reload).

Store the FSA key at the digit length M0 records, restoring only leading
zeros Excel dropped. Do not pad a 6-digit FSA key to 8 with `00`.

Locked match order:

1. If stored FSA key length is 8: unique in-scope directory `opeid` → that
   `school_id`. Zero or more than one exact hit → unmatched.
2. Else (6-digit key, or 8-digit unmatched): unique in-scope
   `main_campus = true` row for that `opeid6` → that `school_id`.
3. Else unmatched (zero mains, more than one main, or no directory hit).

Then collapse to **one row per `school_id`**: prefer an exact 8-digit match;
if none, keep a single 6-digit/rollup; if two or more rollups remain, omit.
M0 must count `school_id`s that would receive more than one matched FSA row
before collapse.

Never fan one rate to every branch. Unmatched branch slugs omit the KPI (same
as a null Scorecard cell). No "see parent campus" copy. Sub-institutional year
pages keep the existing `OutcomesBand` skip.

Foreign and closed schools follow directory `in_scope` / `currently_operating`.

### Privacy and units (locked for M2)

- Persist source suppression tokens and denominator on facts. Never interpolate.
- Persist `nonpayment_rate` as a 0–1 fraction. Convert at load if the
  workbook is 0–100. Tests: source `25` or `0.25` round-trips to UI `25%`
  (`formatPercent` multiplies by 100).
- `public_visible` on facts is false when suppressed or
  `borrowers_in_denom` is below the cut recorded in M0 (if the file has no
  published cut, default **n < 10**, Scorecard-style). Grant SELECT on facts
  and keep `security_invoker` on the view, same as `ipeds_facts`. Never grant
  a stored rate for omitted rows without `public_visible = false`.
- Public KPI and `fsa_nonpayment_current` only expose `public_visible`
  rows.
- M0 must record: header row, OPEID digit length, whether the rate is 0–1 or
  0–100, suppression tokens, and which date in the file is the public as-of
  (delinquency pull date, not the folder month or announcement date).

### Data model

- `fsa_releases`: one row per workbook file. `as_of_date` (pull date from the
  file), `cohort_window_*`, `source_url`, `source_sha256`, `announcement_url`,
  `downloaded_at`. Unique on `source_sha256`. Same as-of + new sha is a
  replacement vintage (ED correction), not a second current row.
- `fsa_nonpayment_facts`: raw FSA. PK `(release_id, opeid)` where `opeid`
  is the FSA key at M0 digit length (leading zeros restored, width not forced
  to 8). Rate (0–1), counts, raw institution name, suppression flag,
  `public_visible`. No `school_id`, no stored `join_status`.
- `fsa_nonpayment_current`: **one global current release** (max `as_of_date`,
  then latest `downloaded_at` if two files share that as-of). Join that
  release to in-scope directory via the match order above. One row per
  matched `school_id`. Schools absent from that vintage omit the KPI. Public
  RLS, `security_invoker`, facts granted but filtered by `public_visible`.
- Do not stuff FSA into `ipeds_facts` or `scorecard_summary`.

`--apply` upserts `fsa_releases` on `source_sha256` and replaces that
release's fact rows. A new sha inserts. Reloading the same file is
idempotent.

### Loader, tests, cadence

- `tools/fsa/`: download immutable cache under `scratch/fsa/<as_of>/`, dry-run
  report, `--apply`. Operator-run from fresh `main` after the migration is on
  `main`.
- Drift guard: abort if expected columns rename.
- M1 tests: pad directory OPEID to 8 (`opeid6 = left(opeid, 6)`); do not
  pad 6-digit FSA keys to 8; round-trip one vintage; rate 0–1; idempotent
  `--apply`; fixtures from the M0 spike (UEI, Miller-Motte, UF at minimum).
- M1 loads every vintage M0 can still fetch. M0 must record workbook URL +
  sha256 for Jul 2025, Feb 2026, and May 2026, or explicitly write "only the
  current file is still hosted" and then M1 loads only that file. No silent
  skip of older vintages.
- M3 probe: monthly Action that hashes
  `https://studentaid.gov/sites/default/files/fsawg/datacenter/library/nonpayment-rates.xlsx`
  (stable filename; new vintages overwrite). The public link is listed on
  [Student Aid Data → Portfolio](https://studentaid.gov/data-center/student/portfolio)
  (in-page search: `nonpayment`). Not on Default Rates (CDR) and not under
  School Data. Do not scrape Knowledge Center HTML as the primary signal.
  Do not scrape NSLDS. No-op until the first load exists.

### Public product

Label locked: **Nonpayment**. Hint: `FSA · as-of {date} · not the official
cohort default rate`.

Fetch FSA independently of Scorecard. Render the federal-outcomes band when
Scorecard **or** a current FSA row exists. Show "federal outcomes data not
available" only when both are missing. Put the FSA number in the band with
its own hint. Do not let the section-level `SRC · COLLEGE SCORECARD` line

API: document `fsa_nonpayment_current` on `/api`. Also document new directory
`opeid` / `opeid6`.

Copy: one-line disclaimer. Publish the figure; do not interpret motive.

Leave Scorecard CDR/repayment off the school page. After M2, a methodology note
may contrast definitions. Do not show both as peer KPIs.

M4 (not the first PR): `/recipes/` at ED's **≥25%** cut, paired with Scorecard

`docs/ARCHITECTURE.md` gets a pipeline-12 paragraph when M1 actually loads

## Data flow (M0 + M1)

```
FSA xlsx (scratch/fsa/<as_of>/)
        │
        ▼
  parse OPEID as text (never int()-length as grain)
        │
        ▼
Scorecard CSV OPEID/OPEID6/UNITID/MAIN
        │
        ▼
  match_fsa_row()  [same function in M0 report and M1 loader]
        │
        ├── unmatched → school_id NULL, logged
        └── matched  → school_id stamped on facts
        │
        ▼
fsa_releases (unique source_sha256)
fsa_nonpayment_facts (release_id, opeid) + school_id + public_visible
        │
        ▼
fsa_nonpayment_current
  = latest as_of_date (then downloaded_at)
    WHERE public_visible AND school_id IS NOT NULL
```
