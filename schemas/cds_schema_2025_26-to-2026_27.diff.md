# CDS canonical schema diff: 2025-26 to 2026-27

Written from `schemas/cds_schema_2025_26.json` and `schemas/cds_schema_2026_27.json`. There is no
`.diff.json` for this pair on purpose: 2026-27 keeps every 2025-26 question number with the same meaning,
so each 2026-27 field is its own canonical field id and the projection needs no equivalence file
(`load_field_equivalences` reads every `*-to-*.diff.json` it finds). `tools/extraction_worker/test_schema_2026_27.py`
checks everything on this page against the two schema files.

## Summary

- 2025-26 fields: 1105
- 2026-27 fields: 1117
- Removed: 0
- Added: 12
- Renumbered: 0 (section, subsection, category, student group, cohort, residency, unit load, sex and value type are identical for all 1105 shared numbers)
- PDF form name changed: 3
- Reworded with the same meaning: 12
- Only the year in the wording changed: 27

## PDF form names that moved

The new Total row under the C1 table by sex took the form names the residency table's Total column had in
2025-26, and the residency totals got new names. A 2026-27 fillable PDF read with the 2025-26 schema would
file the by-sex totals under `C.116`-`C.118` and drop the residency totals.

| Field | Question | 2025-26 form name | 2026-27 form name | Now carried by |
|---|---|---|---|---|
| `C.116` | Total first-time, first-year students who applied | `AP_RECD_1ST_N` | `AP_RECD_1ST_RES_N` | `C.1T01` |
| `C.117` | Total first-time, first-year students who were admitted | `AP_ADMT_1ST_N` | `AP_ADMT_1ST_RES_N` | `C.1T02` |
| `C.118` | Total first-time, first-year students who enrolled | `EN_TOT_1ST_N` | `EN_TOT_1ST_RES_N` | `C.1T03` |

## What the code does with this

- The tier 4 cleaner, the projection and the sanity rules treat 2026-27 as the 2025-26 numbering.
- `C.116`-`C.118` stay the applied, admitted and enrolled totals. When they are blank, the projection uses
  the printed Total row by sex (`C.1T01`-`C.1T03`) before it sums the rows by sex.
- Tier 1 (spreadsheet) and Tier 2 (fillable PDF) read all twelve new fields through the template's own cell
  map and form names, when the file is on the 2026-27 form. A file dated 2026-27 that was built on the
  2025-26 form carries none of the new names; the worker detects that (`resolve_schema_for_form`) and reads
  it with the 2025-26 schema.
- The tier 4 cleaner (flattened PDFs) reads the text, where the two forms share their numbering. It does not
  read the twelve new fields yet.
