# ops

Operator and CI automation scripts for the pipelines: health checks, heartbeats, alerts, controlled directory drains, and workflow linting. None of these own data; they read live Supabase state or call the Edge Functions. Most accept `--env <path>` (default `.env`) and use the shared `tools/extraction_worker/.venv` environment. Write run artifacts to `scratch/ops/`.

## Used by GitHub Actions

| Script | Purpose |
|---|---|
| `record_heartbeat.py` | Writes a pipeline-observation heartbeat via `record_pipeline_heartbeat` (feeds `/pipeline-observation`). Never fails the calling job: a POST error prints a `::warning::` and exits 0. Flags: `--station`, `--status`, `--trigger`, `--summary`, `--summary-json`, `--error-code`, `--run-url`, `--pr-url`. |
| `upsert_pipeline_alert_issue.py` | Opens (or comments on) a single GitHub "Pipeline alert" issue when a scheduled station fails, instead of spamming. Flags: `--repo`, `--component`, `--title`, `--body`, `--run-url`. |
| `notify_discord.py` | Posts ops events to the Discord webhooks (`ops-discord-notify.yml`, hourly). Posts only on first miss and on recovery; never fails the job; never prints webhook URLs. See [`docs/ops-discord.md`](../../docs/ops-discord.md). |
| `enqueue_changed_seeds.py` | After `tools/finder/schools.yaml` changes on `main`, enqueues archive work for the schools whose seed changed so they do not wait out the 7-day cooldown (`ops-archive-seed-catchup.yml`). `--before`, `--after`, `--apply`. |
| `top100_coverage.py` | Scores the priority-100 cohort (`data/watchlists/priority_coverage.yaml`) against the two-year byte bar and routes residential-allowlisted schools (`data/watchlists/residential_allowlist.yaml`) to the headless archive workflow. Coverage means finder and archive, not extraction. |
| `revalidate_pages.py` | Refreshes cached school pages after data changed, through the web app's `/api/revalidate`. `--changed-since-hours N` is the daily sweep (`ops-page-refresh.yml`); `--school-id` refreshes named schools after a hand-run edit; `--all` expires every page (run it after an IPEDS, FSA or Scorecard load). `--dry-run` sends nothing. Prints counts only. |
| `lint_gha_heredocs.py` | CI check: fails on indented bash heredoc terminators inside `run: |` blocks, which GitHub Actions leaves indented so bash never closes the heredoc. Run `python tools/ops/lint_gha_heredocs.py` before pushing workflow edits. |

## Operator tools

| Script | Purpose |
|---|---|
| `automation_health.py` | One-command health check of the automated archive and extraction workers (database state plus recent GitHub Actions runs). `--hours`, `--json-out`, `--markdown-out`, `--fail-on-unhealthy`. |
| `extraction_backlog_audit.py` | Reports the `extraction_pending` backlog after archive or directory drains and optionally checks the extraction worker's last successful run. `--max-pending-age-hours`, `--max-pending-count`, `--fail-on-pending-growth`, `--json`. |
| `directory_enqueue_batches.py` | Controlled batches of `directory-enqueue`. Dry-run by default; `--apply` enqueues and drains staged batches, with transient-failure and stall gates. |

| `duplicate_slug_audit.py` | Read-only audit of active `cds_documents` filed under non-canonical alias slugs, using `institution_slug_crosswalk` and `institution_directory`. |
| `bootstrap_collegedata_ops.sh` | Creates the private `collegedata-ops` repo and pushes the bundle in `ops/collegedata-ops/` (requires a token that can create private repositories). |

## Discovery renewal and the monthly hand check

These tools come from the stale-seeds postmortem ([`docs/postmortems/2026-11-24-stale-discovery-seeds.md`](../../docs/postmortems/2026-11-24-stale-discovery-seeds.md); each control, its test and what it leaves uncovered are in the [prevention ledger](../../docs/postmortems/2026-11-24-stale-discovery-seeds-prevention.md)). The headline number is current-year renewal: of the schools with a live document filed under the previous CDS year, the share that also have one filed under the current year (`cds_freshness_floor()`; `unknown` years don't count). Tracking issue: #460.

Two workflows run them:

| Workflow | When | What it runs |
|---|---|---|
| `ops-discovery-renewal.yml` (`Ops discovery renewal`) | Daily, 13:41 UTC; `workflow_dispatch` defaults to a dry run in test mode | `discovery_renewal.py`, then `fetch_failures.py`, then `renewal_alarm.py`, then the `discovery_renewal` heartbeat, then the outside check-in and `consecutive_failures.py` |
| `ops-hand-check.yml` (`Ops monthly hand check`) | The 3rd of each month, 15:07 UTC; `workflow_dispatch` defaults to a dry run in test mode | `fetch_failures.py`, then `hand_check_sample.py`, then opens the issue. No heartbeat station |

| Script | What it does | Run by hand | Tests |
|---|---|---|---|
| `discovery_renewal.py` (#474, #493, #499, #502, #505, #508) | Computes the headline number for the current year, the two-year check and (from March) the next year, and the per-year arrivals check. Floors are the posting curve (months since the CDS year's fall) scaled by mature renewal, less 5 points for the one-year and two-year checks (the next-year floor is the scaled curve × 0.75, no margin); mature renewal is the median of the last five mature year-pairs of the same manifest, bounded, with a fallback when fewer than three pairs are usable (#508). Writes the summary (heartbeat keys), the report, a state file (including the measured `maturity`), the seed ages, the worklist and per-year reports. Fails loudly on a short or empty read, a previous-year denominator under 350 schools, or a freshness floor that disagrees with the database; being below a floor is not an error (exit 0). | `python tools/ops/discovery_renewal.py --out-summary scratch/ops/renewal-summary.json --out-report scratch/ops/renewal.md --out-state scratch/ops/renewal-state.json`. Reads the public API (`SUPABASE_ANON_KEY` is the public anon key). `--manifest-json` computes from a local snapshot with no network; `--backtest-month-ends 2026-05..2026-11` replays month ends (it needs `--manifest-json`). `--test-mode` with `--floor-override-pct` is test only | `test_discovery_renewal.py` (and `test_heartbeat_key_registry.py`, which checks every summary key against the station's allowed keys) |
| `renewal_alarm.py` (#474, #493, #499, #502, #505) | Opens, updates and closes the alarm issues from the state file: one per scope, `renewal:<Y>` and `arrivals:<Y>`, found by label `alarm:discovery-renewal` and assigned to the owner. Updates a standing issue without commenting, supersedes it every 30 days (or on a 5-point worsening) while still below, closes it on recovery and retires years two or more cycles old. Posts to Discord #alerts on open, supersede, recovery and retire. Test runs use a different label and a `[test] ` title prefix and cannot touch a real alarm issue. What posts and when: [`docs/ops-discord.md`](../../docs/ops-discord.md) | `python tools/ops/renewal_alarm.py --state scratch/ops/renewal-state.json --report scratch/ops/renewal.md --summary scratch/ops/renewal-summary.json --dry-run --test-mode` (`--repo` defaults to `GITHUB_REPOSITORY`, then `bolewood/quadfile`; even a dry run lists issues with `gh`, so it needs `gh` auth) | `test_renewal_alarm.py` |
| `consecutive_failures.py` (#493) | Called from a failing scheduled run. Counts the failed scheduled runs in a row, prints `::error::renewal check has failed N days running`, and posts to #alerts on every 7th consecutive failure. Never fails the job. There is no dry run: run by hand, it counts the current run as failed and may post, so unset `DISCORD_ALERTS_WEBHOOK_URL` first. | `python tools/ops/consecutive_failures.py --repo bolewood/collegedata-fyi --workflow ops-discovery-renewal.yml --run-id <id>` | `test_consecutive_failures.py` |
| `fetch_failures.py` (#488, #497) | Lists schools whose listing is known but whose current-year file isn't archived, grouped by cause (`blocked`, `viewer`, `section_files`, `dead_link`, `other`, `no_failure_recorded`), from the newest `archive_queue` row per school over 45 days. Merges its counts into the renewal summary and writes a worklist; the hand-check issue carries the list. Needs the service role key (read only); without it nothing is classified and no summary keys are written, never a 0. (#468) | `python tools/ops/fetch_failures.py --out-report scratch/ops/fetch-failures.md --out-worklist scratch/ops/fetch-failures.json` (`--manifest-json` and `--queue-json` for local snapshots) | `test_fetch_failures.py` |
| `hand_check_sample.py` (#471, #497) | Draws 20 random schools (seeded by the month, so a rerun picks the same 20) and writes the issue body with links to each school's own site, to record whether the school has posted a newer CDS than ours. The next month's issue reports the miss rate from the previous answers. Measures the miss rate from outside the pipeline. (#461) | `python tools/ops/hand_check_sample.py --month 2026-12 --out scratch/ops/hand-check.md` (needs `SUPABASE_URL` and `SUPABASE_ANON_KEY`; `--manifest-json` reads a local file) | `test_hand_check_sample.py` |
| `same_year_duplicates.py` (#491) | Finds two or more live documents of one school (and sub-institution) filed under one year, and classifies each group (`misfiled_year`, `year_conflict`, `section_split`, `same_file`, `duplicate`), with undated groups kept apart. The classifier is a pure function (`find_groups`) shared with the renewal report and the extraction scoreboard. Finding duplicates exits 0; a short page or missing column exits 1. (#467) | `python tools/ops/same_year_duplicates.py --json-out scratch/ops/same-year.json --markdown-out scratch/ops/same-year.md` (`--from-json` classifies saved rows) | `test_same_year_duplicates.py` |

The finder side of the same work (`stuck_pdf_seeds.py`, `reprobe_outcome.py`, `seed_age.py`) is documented in [`tools/finder/README.md`](../finder/README.md). The board's Renewal tile and Stuck PDFs lamp read the heartbeats these jobs write (`web/src/lib/pipeline-lamps.ts`, `web/src/lib/pipeline-observation.ts`; #470, #494, #500, #503). The `discovery_renewal` station and the heartbeat history (`pipeline_heartbeat_history`, read through `pipeline_station_history()`, 400 days kept per station) are in migration `20261125020000_discovery_renewal_station.sql` (#469, applied to production 2026-11-25). A new heartbeat summary key must be added to that station's allowed keys, or the heartbeat RPC drops it (`test_heartbeat_key_registry.py` fails when a key is emitted but not registered).
